## Перенос целиком (без изменения схемы вручную)
Нужны PostgreSQL 18 command line tools: `psql`, `pg_dump`, `pg_restore`. Источник и получатель должны быть доступны из одного доверенного окружения. Для старого Render использовать *External Database URL* после восстановления и разрешить в Networking **конкретный IP адрес миграционной машины**, а не сеть `0.0.0.0/0`; как альтернативу можно выполнять команды внутри доверенной инфраструктуры с доступом к private/internal DB URL. Neon target — **direct/unpooled** connection string (Console → Connect → Connection pooling OFF, SSL).

Обе переменные — **секреты**: не вставлять их в чат, GitHub, shell history, скриншоты или логи. В доверенной оболочке загрузить их из секретного хранилища в окружение:

- `SOURCE_DATABASE_URL` — старый `shaurma_city_db` Render
- `TARGET_DATABASE_URL` — новый `shaurmeg` Neon
- `SHAURMEG_BACKUP_DIR` — отдельный каталог резервной копии, **вне репозитория**
- `SHAURMEG_WRITES_FROZEN=YES` — только после фактической остановки всех изменений на старой БД

Запустить из корня репозитория:

```bash
bash scripts/migrate-shaurmeg-db.sh
```

Скрипт:
- проверяет оба имени БД, версии PG18 и что **принимающая БД пуста**;
- создаёт полный custom-format `pg_dump` (включая схемы, данные, таблицы, последовательности, индексы, ограничения, large objects);
- сохраняет исходный дамп отдельно (не удаляет его при завершении);
- выполняет `pg_restore --single-transaction --exit-on-error --no-owner --no-acl`; при ошибке импорта откатывает транзакцию;
- сверяет количество строк в каждой таблице, materialized views, число объектов и значения последовательностей;
- **не меняет `DATABASE_URL` и не удаляет исходную БД**.

При ошибке сверки **не переключать production**. При неизвестных расширениях или недостаточных правах Neon необходимо устранить проблему, не изменяя оригинальный Render. Так как target должен быть пустым, не пытаться просто повторить восстановление поверх частично скопированной БД.

## Контроль бизнес-данных перед переключением
Проверить полноту и корректность критичных сущностей:
- `shaurma_venues` (заведения и меню)
- `shaurmeg_markers` (карта, координаты, RealCity-профили)
- `shaurma_users` (Telegram ID, избранное, профиль)
- `shaurma_orders` (все заказы и статусы)
- таблицы заказов кухни, аудит, owner/admin, ключи, quick-order intents, RealCity-фото и metadata
- наличие функций, индексов, foreign keys и последовательностей ID

Проверить работоспособность запуска приложения, webhook ботов, realtime/стримов и связи кухни **на изолированной тестовой конфигурации с копией БД** без отправки реальных заказов или уведомлений пользователям.

## Переключение на новую БД
1. Сохранить старую `DATABASE_URL` **в отдельном секретном менеджере** для rollback.
2. На **единственном production API Render** (`shaurma-city-api`, service `srv-dandcbmgekts738jqs80`) заменить **только** `DATABASE_URL` на direct/pooled Neon URL в соответствии с Node `pg` pool-конфигурацией; не менять API URL, Telegram/webhook токены и app URL. При выборе pooled строк учесть PgBouncer semantics; Node runtime поддерживает обычный TLS Postgres URL. Для импорта всегда direct URL.
3. После деплоя проверить, что в API логах не осталось `ENOTFOUND`, миграции/DDL корректно выполнились, `/api/v2/map/points` возвращает реальные точки. Проверить профиль, favorites, menu, status+history, owner/admin, кухня, RealCity, и только потом разрешить writes.
4. Включить мониторинг соединений, автоматический PITR/snapshots по тарифу, отдельные выгружаемые `pg_dump` копии в другом хранилище, ротацию credentials. Нельзя хранить единственную резервную копию в той же базе.
5. **Старую базу Render не удалять** до подтверждения целостности и успешной работы после cutover; организовать rollback на прежнюю `DATABASE_URL` до запуска новых записей, иначе появится расхождение заказов.

## Ограничения на текущий момент
- **Новая БД создана, но скопировано 0 таблиц** — это сознательно, чтобы избежать ложного переключения.
- База Render приостановлена, её internal host не разрешается в работающем API (`ENOTFOUND`). Hosted Render Connector сообщает также, что внешние подключения запрещены текущим IP allowlist, поэтому прямая выгрузка отсюда пока невозможна.
- Нужное ручное действие: **повысить тариф старой базы Render, пока не истёк 14-дневный grace period**. После возобновления сделаем перенос и реальное переключение.
- Neon Free годится для первичной подготовки, но не заменяет production SLA, бэкапы и масштабирование платного тарифа.
